# A 股与港股通研究数据核查（2026-11-02）

## 结论

现有 A 股缓存有较好的行情基础，但尚未完成历史股票池、价格口径、交易日历与风险验收。
港股通本地行情、历史资格和执行模型目前不具备直接研究条件。
因此不能现在就把两个市场放进同一回测，输出可信的月收益或最大回撤结论。

本轮未下载行情、未连接 Oracle/Wind/QMT、未读取凭据内容、未修改缓存或真实账本，策略注册表继续为空。

## 核查方法与边界

- 逐一检查 `data_cache/kline/` 下 5,845 个 Parquet 文件的元数据：行数、字段和日期统计。
- 检查现有估值矩阵及公司行动文件的元数据。
- 检查数据源、交易规则、回放与风控代码，并对照港交所官方资料确认港股通建模要求。
- 用 `python main.py data audit` 可重新执行只读、离线的汇总核查；详细机器报告保存在本次临时工作目录 `ai-created/data_readiness_2026-11-02.json`。
- 文件名分类仅是库存线索，不是证券主表，也不能证明上市身份、历史可买资格或完整的退市股覆盖。
- 本轮没有逐行检验全量行情，也没有证明所有股票都具有连续日期、正确单位或相同历史覆盖。

## 代码能力与阻断项

| 优先级 | 问题与证据 | 可能后果 | 处理方案 |
|---|---|---|---|
| P0 | 港股行情为零；`data/wind_db.py` 的港股入口默认关闭，字段单位仍标注未验证 | 没有基础输入，或启用后以错误单位做流动性筛选 | 明确数据来源，先小样本验证 raw/adjusted、股数、金额和货币，再规划增量补齐；不直接打开开关 |
| P0 | 缺少已接入的历史港股通资格，文件名无法提供资格生效日 | 今天的名单覆盖历史，产生时点错误；把仅可卖标的当作可买 | 建历史身份/资格表，记录通道、有效区间、可买/可卖状态与来源证据 |
| P0 | `trading/rules.py` 对 HK 的默认数量为 1、固定价格档位仍为 0.01；费用只有通用 A 股假设 | 合法申报量、成交价和净收益失真 | 引入按市场、证券和有效日期区分的手数/报价档位/费用模型；缺元数据拒绝回测该市场 |
| P0 | 回放账本为单一数值口径，未接入港股通汇率和结算估值 | 跨币种净值和 15% 风险指标不可信 | 确定账户本位币口径，按日期处理估值汇率、换汇成本和可用资金；不能直接相加 HKD 与人民币金额 |
| P0 | `live/risk_gate.py` 清仓重入后设置 dd_anchor，且没有完整月度亏损门槛 | 累计损失可能被重新计锚隐藏，月度风险未真正执行 | 根据 RESEARCH_MANDATE 构建不可跨月/重入重置的账户峰值和逐日月度基准；加入跨月、出入金、清仓重入故障测试 |
| P1 | A 股历史股票池来自按日行情或缓存文件集合，没有完成证券主表与状态核对 | 把停牌、退市、上市时间和数据缺失混为一谈，扭曲回测 | 联合历史身份、上市退市、ST、停复牌与行情覆盖；保留退市样本，不沿用起点固定池 |

| P1 | 公司行动缓存仅按文件存在判断命中，未验证请求区间覆盖或新事件更新 | 缓存存在但漏事件，造成幻影亏损或错误股数 | 增加数据来源、覆盖范围和更新时间元信息，按缺口补齐；本轮不改已有文件 |

当前目标下，两项 15% 限制是策略验收条件，不承诺真实市场一定能在风险线上成交。
停止买入、提前降仓、成交失败和压力情形要进入验证，不能靠删除亏损月份或重置净值来满足指标。

## 后续实施顺序

1. 先落地统一月收益/账户回撤度量与无重置风险约束，A 股及港股通共用评价口径。
2. A 股先核对历史证券身份、交易日历、逐行数据质量与公司行动覆盖，复用现有缓存，不重下全量数据。
3. 同步核实港股通历史资格及行情等数据源的可得性；确认覆盖与成本后再接入，不用全部港股或当期名单替代历史池。
4. 完成港股通证券单位、报价、历史费用、币种及通道日历模型后，才能做两市场可比的回放。
5. 数据与度量验收后，再预注册第一批个股策略假设；ETF 信号只作辅助，不恢复独立 ETF sleeve。
