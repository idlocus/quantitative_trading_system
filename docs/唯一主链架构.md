# 唯一主链架构（回测与实盘语义统一）

> 版本：2026-10-12 ｜ 模块：`trading/`（新增共享层）｜ 守护测试：`tests/test_chain_consistency.py`

## 1. 背景与问题

项目同时存在 `backtesting/engine.py`、`portfolio/backtester.py`、`strategy/`、`selection/`、`live/` 多套交易语义，容易出现"测试通过，但生产链路使用了另一套逻辑"。本轮审计坐实的分叉：

| 环节 | 回测（portfolio/backtester） | 生产（live/） | 后果 |
|------|------------------------------|---------------|------|
| 缓冲带默认 | **0**（全量换仓） | 0.20 | 回测默认口径 ≠ 生产口径 |
| 流动性过滤 | 500万日均额（不可买） | **无** | **生产买入日均成交额仅4-19万的北交所标的，回测从未买过** |
| 涨跌停判定 | 板块比例（10/20/30%） | `\|chg\|≥9.8%` 一刀切 | 北交所30%板、创业/科创20%板系统性误判拒单 |
| 费用率 | 硬编码 | 硬编码 + risk/constants 第三份 | 值相同但三处定义，改一处漏两处 |
| 因子/TopN/上市天数 | 各自硬编码 | 各自硬编码 | 同上 |

## 2. 主链定义

```
数据快照 → PIT因子 → 信号 → 目标组合 → 订单 → 成交模拟/真实成交 → 账本 → 净值与归因
```

共用组件（`trading/` 包，单一事实来源）：

| 组件 | 位置 | 回测接入 | 生产接入 |
|------|------|----------|----------|
| 主链参数 | `trading/config.py` | `PortfolioConfig` 全部默认值 | `live/signals.py` 常量 re-export |
| 交易规则（涨跌停/整手/费用） | `trading/rules.py` | `_limit_ratios → limit_ratio_series` | `PaperBroker → is_limit_up/down` |
| 因子合成 | `portfolio/construction.py` | run_portfolio_backtest | `live/signals.generate_target` |
| 选股过滤（上市天数/流动性） | 同口径阈值 | `_select + _liquidity_mask` | `generate_target + illiquid_set` |
| 缓冲带 | `chain.BUFFER_BAND` | `PortfolioConfig.buffer_band` | `build_orders(band=...)` |

**允许的差异（刻意保留）**：

| 差异 | 回测 | 生产 | 理由 |
|------|------|------|------|
| 成交执行器 | 向量化模拟（含市场冲击 sqrt 模型、参与率约束） | PaperBroker / QMTBroker | 回测保守假设 vs 真实成交 |
| 风控层 | `risk_manager`（研究约束） | `risk_gate`（L2-L4 强制执行） | 阈值同源（`DRAWDOWN_SOFT/HARD`），职能不同 |
| 调仓节奏 | 每 N 交易日重选（近似口径） | 每日重选 + 缓冲带控换手 | **非严格等价**（见下） |

**调仓节奏不是严格等价**（2026-10-12 第四轮修正此前错误论断）：缓冲带只控制已持仓的权重漂移，不控制排名进出——跌出 TopN 的持仓当日立即卖出、新进 TopN 当日买入、风控闸门逐日注入强制卖单，这些每日语义在"每N日近似回测"中无法表达。**严格验证生产收益用每日重放回测器**（`portfolio/daily_replay.py`）：

```
T-1收盘信号（PIT过滤，与generate_target同口径）
  → live.signals.build_orders（缓冲带，与生产同一函数）
  → live.risk_gate.RiskGate（L2/L3/L4，与生产同一实现）
  → live.broker.PaperBroker（同费用/板块涨跌停/整手）
  → live.ledger.Ledger（同入账去重/净值）
```

不重写第二套逻辑——回测即生产的时间机器。运行：`python run_daily_replay.py --universe 500 --years 3 --compare`（`--compare` 同数据再跑5日近似回测做 A/B 对比，量化两种口径的收益差）。

**真实数据 A/B 实测（2026-10-12，universe=150、Top30、近1年，含风控闸门）**：

| 指标 | 每日重放（生产语义） | 5日近似回测 |
|------|----------------------|-------------|
| 总收益 | -4.08% | -5.82% |
| 最大回撤 | -14.47% | -14.70% |
| 累计成本 | 10,823（1.08%本金） | 4,959 |
| 交易频率 | 217 个有成交日 | 49 次调仓 |
| L4 止损卖出 | **162 笔** | 0（无此语义） |

结论：每日排名进出使成本翻倍、L4 止损逐日触发（162笔/年，且含"止损后次日回买"的churn）——这些真实生产行为在5日近似口径中完全不可见，**生产收益必须以每日重放口径验证**。已验证的每日语义（tests/test_daily_replay.py）：排名跌出当日卖、新进当日买、L4止损逐日注入、T-1信号无前视、基准缺失停机。

**旧链定位（不在主链上）**：`backtesting/engine.py` + `strategy/` + `selection/` 是个股止损型策略引擎（研究遗留，另一个产品形态），与生产因子链不共享语义，勿相互引用。

## 2.1 执行时序（前视防护，2026-10-12 第二轮补强）

**修复前的前视问题**：`run_pm`/`run_live` 用 `generate_target(date.today())` 生成信号并以当日收盘价成交——信号已使用当日完整收盘数据，却假设能以当日收盘价成交，真实交易不可实现。且 AM 预览用 T-1 信号、PM 执行重算 T 日信号，早晚单子不一致。

**主链唯一时序口径**：

```
信号：T-1 收盘数据（PIT）          ← signal_date_for()：严格早于执行日的最近完整交易日
执行：T 日                          ← 回测/Paper 以 T 收盘价+滑点撮合；QMT 在 T 日盘中/收盘竞价下单
```

与回测 `score_mx.shift(1)`（调仓日 t 用 t-1 分数、t 收盘价成交）**完全同构**。

实现要点：
- `live/signals.py::generate_production_signal()` 是生产信号唯一入口（run_daily / run_live / journal 一律经由它）
- `signal_date_for()` 在盘后运行（当日 bar 已存在）时自动再往前推一个交易日，杜绝"当日信号+当日收盘价"
- 守护测试 `TestExecutionTiming`（5 项）：信号日严格先于执行日、盘中/盘后两种运行形态、源码级禁止绕过入口、回测 shift(1) 锁定、AM/PM 同信号

## 2.2 执行器接通（2026-10-12 第三轮补强）

**修复后**：

1. **单一 QMTBroker**：删除 `broker.py` 占位类；`live.QMTBroker` 唯一指向 `qmt_broker.QMTBroker`（完整实现：连接/委托/部分成交/撤单/成交回报 `fetch_statement`）。
2. **执行器工厂** `live.make_broker(mode)`：`paper` 即用；`qmt` 先跑 `check_env()`，未就绪抛**带逐项修复指引的 RuntimeError**——绝不静默跳过。
3. **CLI 真实接通**：
   - `run_live.py --signal --execute qmt` → 构造 QMTBroker → 交互二次确认（显示委托条数与买入合计金额，`--yes` 免确认）→ 委托 → 入账（去重）→ 提示立即对账
   - `run_daily.py --phase pm --execute qmt --yes` → 同路径；无人值守缺 `--yes` 时拒绝提交并保留指令

4. **成交回报ID贯通**：QMT Fill 携带订单号 `trade_id` → 账本 dedup 优先键，回报重放不重复入账。
5. **守护测试**（`tests/test_qmt_wiring.py` 12 项）：单一类解析、`__all__` 全可解析、工厂各模式、源码级禁止静默分支与占位文案回归。

当前状态：Paper 全链路可用；QMT 通道代码就绪、CLI 已接通，等待券商环境（`--check-qmt` 三项：QMT_PATH / QMT_ACCOUNT_ID / xtquant）后做端到端验证——首次实盘建议先小额、当日 `--statement` 对账。

## 2.3 回测风控真接线（2026-10-12 第五轮补强）

**修复前的三处名不副实**：`RiskLimits.drawdown_derisk=0.10` ≠ 生产 8%（守护测试 ±3% 容差放水）；`check_turnover`/`check_market_circuit_breaker`/行业约束在 `RiskLimits` 中声明但回测主流程只调用了 `adjust_weights()`+`update()`；文档"已具有行业集中度、换手上限、市场熔断"表述过强。

**修复后**：

1. **阈值真同源**：`RiskLimits` 与 `GateConfig` 全部阈值（回撤软/硬限、市场/组合单日熔断）取自 `trading/config`；守护测试改为**精确相等**断言（删除 ±3% 容差）。注意：回测回撤软限 0.10→0.08 是行为变化（更早降仓），旧口径复现需显式传 `RiskLimits(drawdown_derisk=0.10)`。

## 2.6 成交额单位修正（2026-10-12 第八轮补强，影响最大的一处数据错误）

**实证结论**（600527.SH 2026-10-09 三方比对）：DB `ASHAREEODPRICES` 的 `S_DQ_VOLUME`=手、`S_DQ_AMOUNT`=千元；Wind 客户端 wsd volume=股、amt=元。此前回测与生产用 `close×volume` 计算成交额，而本地缓存 **5765/5768 只**含 DB 手单位行 → 成交额系统性**低估 100 倍**。连带后果：流动性过滤（500万门槛）错误排除大量合格股票、参与率约束错杀买入量、冲击成本虚高百倍。另一个连带修复：指数表 `AIndexEODPrices` 无 `S_DQ_ADJ*` 列，此前沿用个股列名导致 ORA-00904、DB 层数据被连坐丢弃。

**修复**：

1. **数据层归一化**（单一口径：volume=股、amount=元）：DB 读取 volume×100、amount×1000 并新增 `amount` 列；客户端新增 `amt`→`amount` 列；指数表改用正确的非复权列名。
2. **共享计算**：`data/turnover.py::avg_daily_turnover`（amount 优先，缺失退化 close×volume）；回测 `avg_turnover_20d` 与生产 `illiquid_set` 统一经由它取数，禁止消费端再自算。
3. **缓存迁移**：`scripts/migrate_kline_units.py` 用 DB 逐日精确比对判定单位（ratio=1→手行×100；ratio=100→已是股），同时回填 amount、剔除历史残缺行；已执行（5765 只修复，备份于 data_cache/kline_backup_units）。
4. **生产影响实测**：迁移后 920275.BJ 真实日均额 19万→**1199万**（合格），600527.SH 2154万→7216万；生产信号北交所标的从 0 只回流 **24 只**——此前它们被错误排除。

## 2.7 QMT 订单生命周期（2026-10-12 第九轮补强）

**修复前的账本延迟风险**：`_wait_for_fill` 超时返回 `(SUBMITTED, 0, 0.0)`——期间已发生的部分成交量被直接丢弃，账本直到对账才能补回；期间信号/风控/下单全部基于低估的持仓。另有隐藏 bug：`execute()` 仅在 `status=='filled'` 时扣减运行现金，部分成交不占用资金。

**修复后的完整生命周期**：

```
提交（登记在途台账 qmt_orders.json）
  → 等待终态（order_timeout，默认30s；超时自动撤单——收盘执行不留隔夜在途单）
  → 增量入账：本次已成交 − 台账已入账；trade_id = "{订单号}#{累计成交量}"（幂等）
  → 撤单残量：CANCELLED 不立即清退，sync_pending 复核一次后再清（撤单瞬间可能仍有成交）
  → 崩溃/次日恢复：sync_pending(ledger) 在生成信号之前执行（先补账本，再算风控与订单）
  → 台账清退：FILLED/REJECTED 即清；CANCELLED 复核后清；TTL 3天兜底（僵尸记录交对账）
```

设计要点：
- **幂等键** `oid#累计量`：同一订单的分笔补记各自独立（600→`ORD1#600`，涨到1000→`ORD1#1000` 补400），回报重放/重复同步被账本去重
- **先补后算**：`run_daily` pm 与 `run_live --signal` 在 `generate_production_signal` 之前调用 `sync_pending`（有源码级守护测试锁定顺序）
- **可测试性**：`_submit_order/_query_order/_cancel_order` 三个原语可注入假实现，8 项生命周期测试无需 xtquant：部分成交入账、跨同步增量、幂等去重、崩溃恢复、撤单残量复核、TTL清退、全量成交、接线顺序

## 2.8 主链 v5 工件与收益结论（2026-10-12 第十轮，`experiments/mainchain_v5.py`）

**结论先行：新主链在两个年代都不赚钱，且相对"无选股能力的同约束组合"几乎没有增益。** v4 的正收益不能用来代表新主链——生成 v5 后证实了这一点。

**三方对照（策略 vs 可交易等权对照 vs 基准，§2.9 定义口径）**：

| 年代 | 策略（近似/重放） | 可交易等权对照（同约束、无选股能力） | 沪深300 | 因子增益 |
|---|---|---|---|---|
| 样本外 2017-2021 | -9.5% / -9.6%（回撤-14.4%，止损396笔） | **-9.9%**（成本0.14%，3034只，资金×31） | +47.8% | **≈0**（+0.4pp/5年） |
| 全市场 2022-2026 | -13.1% / -13.2%（回撤-14.9%，止损232笔） | **-15.6%**（成本0.03%，4685只，资金×47） | -12.2% | **+2.5pp/4.8年 ≈ +0.5pp/年** |

要点：

## 2.13 缩量死锁与硬限停机（2026-10-12 第十一批，审计字段兑现的头号发现）

回放工件审计字段暴露"2024 年起净值纹丝不动"，追查后确认**两层机制**：

**第一层：缩量碎片死锁（bug，已修）**
```
回撤~13% → exposure~1.4% → 每票 9000×0.014≈126元 < 最低下单2000 → 买单全拒
→ 空仓 → 净值冻结 → 回撤永不恢复 → 永久死锁
```
修复：①**缩量预算制**——总买入预算=`exposure×nav−已投市值`，每单按 build_orders 原金额（本就是足额单票）占用预算，耗尽即止，不再"每票×exposure"切碎；②scale+空仓时回撤锚重置（安全网）。

**第二层：硬限清仓终态（设计意图，改为醒目上报）**
```
2024-02-02 回撤≥15% → liquidate 清仓 → 空仓+净值冻结 → 回撤永远≥15%
→ action=liquidate 永续 → 一切订单被拒 → 持币停机至区间末
```
这不是 bug——硬限=停止是风控语义。错的是**静默**：结果文件曾不说明"已停机"。修复：
- 默认 `restart_after_liquidation=False`：清仓完成后闸门留痕"[L3] 硬限清仓已完成，策略停机持币——等待人工决策重启"
- `True`（研究对照/`run_daily_replay --restart`）：锚重置自动重启
- `ReplayResult.terminal_note` 进工件 + `summary_markdown` 醒目 banner："⚠ 终态：XXXX-XX 起空仓停机……区间尾部收益为现金收益，不代表策略持续运行"

**修正后的结论读法**：fullmarket 每日重放 -14.0% = "2024-02 硬限止损离场后持币"——策略在硬限语义下的真实答案；oos -10.3% 为全程运行。此前"A/B ±0.1% 一致"的巧合（近似引擎无金额拒单、各自失真）不再作为实现互证依据，一致性以守护测试为准。

守护测试：`TestScaleDeadlockFix` + `TestLiquidateTerminalSemantics`（默认停机留痕/重启模式恢复交易）。

## 2.20 复权口径断裂修复（2026-10-13 审计最重要发现）

**问题**：journal 显示 600605.SH 盈亏 +4688.8%——根因是**数据复权口径断裂**：
- DB 查询用 `S_DQ_ADJCLOSE`（前复权，600605 的 adjfactor=52.2）
- Wind 客户端返回不复权原始价
- 买入成交时缓存来自客户端（不复权 29.43），后来缓存重建变成 DB 前复权（1409.3）
- 成本 29.43 vs 现价 1409 = 平行宇宙的比较

**影响**：所有持仓成本被低估 30-50 倍→止损永远不触发（-5% 实际变成 -200%+）、净值/回撤/风控全错。

**修复（数据层分离双轨价格）**：
| 列名 | 内容 | 用途 |
|---|---|---|
| `close` | `S_DQ_CLOSE`（**不复权真实市场价**） | 实盘成交、成本记录、止损判断、涨跌停判定、P&L |
| `adjclose` | `S_DQ_ADJCLOSE`（前复权） | 回测净值/收益计算（跨除权连续） |

- DB 查询改为返回 `S_DQ_CLOSE` 为 `close`，新增 `adjclose` 列
- 回测器/重放器 `close_mx`（净值用）改读 `adjclose`；涨跌停判定用 `raw_close_mx`（不复权）
- 缓存版本检测：无 `adjclose` 列 = 旧格式（close 是前复权）→ 自动全量刷新
- Wind 客户端 `adjclose=close` 同值退化（默认不复权，实盘路径正确）
- **此前所有回测/生产结果均受影响**——成本基准错误意味着止损从未正确触发过
