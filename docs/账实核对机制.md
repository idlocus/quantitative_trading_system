# 账实核对机制（Ledger–Broker Reconciliation）

> 版本：2026-10-12 ｜ 模块：`live/reconcile.py` + `live/ledger.py`(v2) ｜ CLI：`run_live.py`

## 1. 背景与问题

JSON 账本此前没有完整处理券商侧的真实世界：成交回报、部分成交、撤单、手续费差异、分红送转、资金流水、持仓不一致、重复执行/重复入账。其中一个已坐实的账实漏洞：`Ledger.apply_fills` 只入账 `status == 'filled'` 的成交，**QMT 部分成交（`partial(600/1000)`）的已成交部分会被静默丢弃**——真金白银的账实分离。真实交易前必须建立每日账实核对。

## 2. 八类问题的对策

| 问题 | 对策 | 位置 |
|------|------|------|
| 券商实际成交回报 | `BrokerStatement.trades` 逐笔匹配（trade_id 优先，要素指纹兜底）；QMT 就位后 `QMTBroker.fetch_statement()` 自动拉取 | `reconcile.py` / `qmt_broker.py` |
| 部分成交 | `quantity>0` 即入账（partial 按实际量记账；撤单/废单零量跳过） | `ledger.apply_fills` |
| 撤单 | 券商无成交、账本有记录 → 报 `trade_missing_broker`（不自动处理，人工核查） | `reconcile._check_trades` |
| 手续费差异 | 匹配上的成交比较费用合计，超容差（默认¥1）报 `fee_diff`，`--fix` 时并入现金修正 | `reconcile._check_trades` |
| 分红和送转 | `apply_dividend` / `apply_split`（事件key幂等，重复执行不重复入账；送转数量×比例、成本÷比例） | `ledger.py` |
| 资金流水 | `cash_log` 全量留痕：trade / dividend / deposit / withdraw / cash_adj，每笔带引用与备注 | `ledger._log_cash` |
| 持仓数量不一致 | 逐票比对报 `position_diff`（区分账本多出=疑重复入账/送转未记 vs 券商多出=疑漏记） | `reconcile._check_positions` |
| 重复执行/重复入账 | `dedup_key`（`id:回报ID` 或 `日期\|代码\|方向\|数量\|价格`）入账去重；同日重复跑 `run_daily` 不再双记；券商回报自身重复也检测 | `ledger.apply_fills` / `reconcile` |

## 3. 每日对账流程

```
收盘后
  ├─ run_daily.py --phase pm --execute paper|qmt   # 交易+入账（自动去重）
  ├─ [QMT] QMTBroker.fetch_statement()            # 自动拉取券商快照（就位后）
  └─ [手工] python run_live.py --statement-template
           → 填 live/statements/今日.json（券商App持仓/资金/成交流水）
  ├─ python run_live.py --statement               # 核对（仅报告）
  └─ python run_live.py --statement --fix         # 以券商为准修正（全部留痕）
```

`run_daily.py --phase pm` 发现 `live/statements/今日.json` 存在时**自动核对**并写入日志"## 六、账实核对"章节；无对账单时显示上次对账状态提醒。

## 4. 差异类型与处理原则

| 差异 | 含义 | `--fix` 自动修正？ |
|------|------|------------------|
| `cash_diff` | 现金不一致 | 是（现金对齐券商，入 cash_log） |
| `position_diff` | 持仓数量不一致 | 是（数量对齐券商，事件留痕） |
| `trade_missing_ledger` | 券商有、账本无（漏记/部分成交丢弃） | 是（按券商回报补记） |
| `fee_diff` | 手续费差异 | 是（并入现金修正） |
| `trade_missing_broker` | 账本有、券商无（撤单误记/重复入账嫌疑） | **否**——人工核查后手动处理 |
| `trade_duplicate` | 券商回报自身重复 | 否（数据源问题，核对要素后忽略或反馈券商） |

原则：**券商为准**（真实持仓/资金以券商为准），但每笔修正都留痕（cash_log / events），`last_recon` 记录在 ledger.meta 供 `--status` 与 journal 展示。

## 5. 对账单格式（live/statements/YYYY-MM-DD.json）

```json
{
  "as_of": "2026-10-12",
  "source": "manual",            // manual / qmt
  "cash": 178476.24,             // 券商可用资金
  "positions": {"600527.SH": 9700, ...},
  "trades": [                    // 可省略：省略则跳过成交级比对
    {"date": "2026-10-12", "symbol": "600527.SH", "side": "SELL",
     "price": 30.85, "quantity": 1000, "commission": 9.26,
     "taxes": 3.09, "trade_id": "20261012000123"}
  ]
}
```

目录已加入 `.gitignore`（含账户敏感信息，勿提交）。


## 7. 验证

- 单元测试：`tests/test_reconcile.py`（18 项：去重/部分成交/公司行动幂等/资金流水/六类差异检测/修正闭环/旧账本兼容）
- 端到端（真实账本123只持仓）：镜像对账单 → `账实一致`；注入持仓+100股/现金-500 → 两项差异均正确报出
- 全量回归：153 项测试通过

## 8. 已知边界

- 手工对账单不填 `trades` 时只核对现金+持仓（成交级核对需填流水或等 QMT 自动拉取）
- `trade_missing_broker` 不自动处理：涉及撤单重报/重复入账判断，必须人工确认后用 `adjust_position`/`adjust_cash` 或反向 trade 修正
- QMT `fetch_statement()` 的税费拆分以交割单为准（回报只有费用合计时 taxes=0，佣金字段承载全部费用）
