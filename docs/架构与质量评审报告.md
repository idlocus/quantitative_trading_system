## 第三部分：根因沉淀

十轮发现的问题并非随机。以下五条是它们反复出现的结构性原因。

### 3.1 关键统计

| 指标 | 评审初期 | 当前 |
|---|---|---|
| 测试全绿时存活的数据事故 | 4 个 | 0 |
| 口径收敛：读路径 | 0 / 5 | **5 / 5** |
| 口径收敛：写路径 | 0 / 5 | **基本收敛** |
| 分层倒置 | 6 处 | **0** |
| 策略构造入口 | 11 个 | 1 + 显式标注的实验入口 |
| 测试数 | 308 | **383** |

### 3.2 根因一：口径靠"复制"而非"复用"保持一致

**表现**：同一语义在多处独立编码（涨跌停 17 处、回撤 11 处、NAV 10 处、费用 9 处）。

**为何约束不住**：项目用"唯一主链"文档 + 一致性测试来保证，但**只能守住"常量值相等"，守不住"逻辑实现相等"**。

> 典型证据：`trading/config.py` 曾有一条注释声称"三处旧定义收敛于此……risk.constants 同值"，实测 `SLIPPAGE` 为 0 与 0.001 不等——**"唯一真源"文件里写着一句自己都没验证过的断言。**

**解法（已验证有效）**：把口径从"常量"升级为"可导入的实现"，并让调用方删除内联算术而非仅共享常量。

### 3.3 根因二：测试的"形状"与 bug 的"形状"不匹配

| 测试验证的 | bug 的形态 |
|---|---|
| 函数返回什么（接口正确性） | 值本身是错的（数据正确性） |

`test_e2e_pipeline.py` 用合成数据，能验证**传导路径**，验证不了**口径真值**。四次事故发生时，308 个测试全绿。

**解法**：测试分三层——接口测试 / 口径一致性测试 / **数据契约测试（抽样真实缓存与数据库）**。第三层是后加的，也是唯一能抓住那四次事故的层。

### 3.4 根因三：校验的严格性本身会成为故障源

第 8 轮建议"契约显式声明、不符即拒绝"，落地第一天就出问题：值域设得太窄，正常信号被判死。

> **契约的价值来自它拦住真正的错误，不是来自它拦得多。**

把"单位错 100 倍"这种硬错误和"某只股票 EP=1.2"这种正常极端值用同一套 `issues/passed` 机制处理，必然误杀。

**解法（已落地）**：契约分级——

| 类型 | 内容 | 违反时 |
|---|---|---|
| 硬契约 | 单位、复权口径、覆盖率 | **拒绝** |
| 软契约 | 数值合理区间 | **告警不拒绝** |

**这可能是十轮里最重要的一条经验**：在量化系统里，没有区分错误等级的"严谨校验"，比没有校验更危险。

### 3.5 根因四：报告层与决策层各算一遍，无人核账

曾发现日报现金比例是恒等式：

```python
w = 1.0 / max(len(targets), 1)
cash = 1 - min(1.0, len(targets) * w)   # ≡ 0 恒成立
```

**这个"错误"活了 7 轮**，唯一原因是没有任何人拿它和实际数字核过账——因为日报与执行是两条独立的计算路径。

**已改为经 `semantics.planned_exposure` / `actual_cash_ratio` 统一。** 结构性风险仍在：只要展示层自己算，就还可能与现实背离。

### 3.6 根因五：新增代码缺少"被验证"的环节

第 10 轮新增约 1100 行运维代码，一夜之间出现三个同类问题：

- 本该启动时读一次的状态 → 变成每次下单都读
- 本该 fail-safe 的开关 → 做成 fail-open
- 本该显式注入的依赖 → 做成隐式全局

三者同源于**新代码未经隔离验证**。评审发现并修正后，这类问题未再复现。
