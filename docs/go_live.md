# 灰度上线流程（Paper → 小额实盘 → 正常）

> 前提：仅管理自有资金。每一步通过后再进下一步，不可跳级。

## 阶段一：Paper 验证（当前）

**持续时间**：至少 2 个月（覆盖不同市场状态）

**通过条件**：
- [ ] 每日信号正常生成（覆盖率>80%）
- [ ] 换手率符合预期（月度调仓，日均<3%）
- [ ] 实际成本与回测假设偏差<50%
- [ ] 止损触发频率合理（每月<20笔）
- [ ] 净值曲线与回测方向一致（不要求完全一致）
- [ ] 无未处理异常
- [ ] `python scripts/preflight_check.py` 全部通过

**退出条件**：如果Paper期间出现不可解释的偏差→停下排查，不进入下一阶段。

## 阶段二：小额实盘灰度

**资金**：总资金的 10-20%（如总100万→10-20万）

**前置**：
- [x] QMT 阻断项全部修复（2026-10-15 订单生命周期重写：
      ① 客户端引用(order_remark)↔真实订单号映射——回调精确关联+兜底扫描，
        替代旧的 seq_ 直查（永远匹配不上→成交丢失）与按 symbol 猜测（并发串单）；
      ② 成交→入账原子化（R4）：先入账成功、后推进/清退台账，入账被阻则
        台账保留待复核；sync_pending 同口径；execute 支持传入 ledger
        （run_daily/run_live 已接线，ATOMIC_LEDGER_BOOKING）；
      ③ 台账原子写（临时文件+os.replace），写一半崩溃不再截断旧台账；
      ④ 8 参数官方签名 ✓（此前已修）；⑤ 查询-1 不可确认即阻断 ✓（此前已修）。
      验证：tests/test_qmt_lifecycle_v2.py 9 项 + 既有生命周期测试。
      **首实盘日仍需人工验证引用映射与成交回报日志**——模拟无法替代真实券商回报）
- [ ] 完成券商程序化交易报备
- [ ] `python scripts/preflight_check.py` 通过
- [ ] `pytest -m release_gate` 通过
- [ ] Kill Switch 测试通过（激活→确认停止→解除）

**运行**：
- Paper 继续跑（作为对照）
- QMT 每日运行（收盘竞价窗口内）
- 每日对账必须成功
- 每周对比 Paper vs 实盘收益差

**退出条件**：
- 实盘 vs Paper 偏差 > 2%（成本/滑点/执行差异）→ 停下分析
- 任何对账不一致 → 立即停止，人工核查

**持续时间**：至少 1 个月

## 阶段三：逐步放大

- 10-20% → 50% → 100%
- 每次放大间隔至少 2 周
- 每次放大前重新运行 preflight check

## 随时可做的事

```bash
# 一键停止
python scripts/kill_switch.py "原因"

# 检查状态
python run_live.py --status

# 实盘前检查
python scripts/preflight_check.py

# 发布门槛
pytest -m release_gate
```
