# 风险分层与执行闸门（Risk Layering & Execution Gate）

> 版本：2026-10-12 ｜ 模块：`live/risk_gate.py` ｜ 集成：`run_daily.py` / `run_live.py` / `live/journal.py`

## 1. 背景与问题

此前生产系统没有真正的组合级保护机制：策略主要通过重新选股调仓，**持仓跌出目标后才可能卖出**。日志中的均线、止损和风险提示（journal 第二节"持仓风险扫描"）只是写给人看的警示，并不等于真实交易中执行了风险控制。典型实例：2026-10-12 日志中 `688807.SH` 已跌破止损线 -8.4%，但当日调仓指令里没有它的卖单——预警与执行之间存在断层。

本次改进建立**执行风控闸门**：位于信号生成与券商执行之间的指令改写层，Paper/QMT 同路径，确保"日志里写了的风险控制，真实交易一定执行"。

## 2. 五层风险口径

| 层级 | 类别 | 位置 | 动作 |
|------|------|------|------|
| L0 | 研究指标 | `live/signals.py`（因子/估值） | 无——仅用于选股 |
| L1 | 预警指标 | `live/journal.py` 第二节（RSI/均线/量比/距止损） | 无——仅日志提示，journal 中明确标注"不触发交易" |
| L2 | 数据停机规则 | `RiskGate._check_data` | **拦截全部指令**（数据不可信时连强制卖出也不执行） |
| L3 | 组合级熔断规则 | `RiskGate._portfolio_breakers` | **缩量 / 禁买 / 清仓** |
| L4 | 实际卖出规则 | `RiskGate._enforce_stops` | **注入强制 SELL**（个股止损） |

优先级：L2（停机）> L3（熔断）> L4（止损）> 原始调仓指令。

## 3. 各层规则明细

### L2 数据停机（action = `halt`）

| 检查 | 阈值（默认） | 后果 |
|------|--------------|------|
| 基准新鲜度 | `000300.SH` 最新K线滞后 ≤5 自然日 | 超过 → 停机（无基准无法判定市场熔断） |
| 价格覆盖率 | 持仓∪目标 ≥90% 有最新价 | 低于 → 停机（数据管道故障） |
| 异常波动占比 | 单日\|涨跌\|>21% 的标的 ≤5% | 超过 → 停机；个别异常 → 仅剔除该标的指令 |

### L3 组合熔断（action = `scale` / `no_buy` / `liquidate`）

| 规则 | 阈值（默认） | 动作 |
|------|--------------|------|
| 回撤软限 | 净值回撤 ≥8%（自账本净值峰值） | 线性降仓：仓位上限从 100% 降到 0%（至硬限）；买入金额×上限；超配持仓从最大开始削减 |
| 回撤硬限 | 回撤 ≥15% | 全部清仓，原调仓指令作废 |
| 组合单日暴跌 | ≤-7% | 禁买冷却 1 天（只卖不买），状态持久化 |
| 基准单日暴跌 | ≤-5% | 禁买冷却 1 天，状态持久化 |

阈值与回测 `portfolio/risk_manager.py::RiskLimits` **真同源**（2026-10-12 起：`drawdown_derisk` 从研究值 0.10 改为 `chain.DRAWDOWN_SOFT=0.08`，与生产闸门精确相等，守护测试无容差断言）。回测侧风控接线状态：回撤降仓/清仓、波动率缩仓（`adjust_weights`+`update`，原有）；换手上限回缩、市场熔断禁买（2026-10-12 接入主流程）；行业集中度（机制就绪，需 `PortfolioConfig.industry_map` 输入行业映射后生效，缺省时不启用并在日志说明）。生效事件计数见 `PortfolioResult.risk_events`。

### L4 强制卖出（注入 SELL 指令）

| 规则 | 说明 |
|------|------|
| 个股硬止损 | 收盘价 ≤ 成本×0.95 → 全仓强制卖出（与 journal L1 扫描的 cost×0.95 同口径） |
| T+1 锁仓 | 当日买入的破止损标的顺延次日（A股 T+1） |
| 单日上限 | 止损卖出 ≤20 只/日，亏损最深者优先，其余顺延（防踩踏） |
| 冲突处理 | 强制卖出的标的自动撤销同日买入指令 |

## 4. 集成点与数据流

```
generate_target()          L0 研究：5因子 Top100
      │
build_orders()             调仓层：缓冲带 20%
      │
RiskGate.review()          ★ 执行闸门：L2 停机 → L3 熔断 → L4 止损 → 指令重组
      │  （改写：拦截 / 缩量 / 注入强制卖出）
      ▼
PaperBroker / QMTBroker    执行层：涨跌停拒单、整手、费用
      │
Ledger.apply_fills()       账本：持仓/现金/净值（净值序列反馈给 L3 回撤计算）
```

- **`run_daily.py --phase pm`**：执行前过闸门；`halt` 时跳过执行并打印原因；PM 日志记录"执行闸门"小节。
- **`run_daily.py --phase am` / `journal.write_am`**：基于昨收做闸门**预览**（第四节"盘前风控检查"），收盘后以当日数据复核执行。
- **`run_live.py --signal --execute paper`**：同样过闸门后才执行。
- **状态持久化**：`live/risk_state.json`（禁买冷却期 `no_buy_until`，跨日生效）。

## 5. 本次同步修复的数据层缺陷（L2 的前置保障）

1. **`data/layered.py::_missing_after`**：原实现只遍历 `results` 中已有符号——DB 整批失败时符号不在 results 里，从缺口中消失，导致第③层 WindPy 客户端兜底永不触发（实测基准 000300.SH 因此取不到）。已改为按请求符号清单重算缺口。
2. **残缺K线行过滤**（`data/wind.py` / `data/layered.py`）：盘中运行时客户端会返回"只有 close、OHLC/volume 全 NaN"的未完成bar（实测污染 65% 持仓的涨跌检测，被闸门 L2 以"异常价格占比"拦截停机）。现于客户端组装、缓存读、合并、写回四处统一剔除不完整行。

> 两层防御的关系：数据层修复让"好数据不误伤"，闸门 L2 保证"坏数据必停机"。

## 6. 实际效果（2026-10-12 真实账本验证）

当日 journal L1 预警"⚠逼近止损"的持仓，闸门生成了 4 笔实际强制卖出指令（亏损最深优先）：

| 代码 | 止损幅度 | 动作对比 |
|------|----------|----------|
| 688807.SH | -13.0% | 改进前：仅日志警示，继续持有 → 改进后：**强制全仓卖出** |
| 688759.SH | -7.7% | 同上 |
| 688582.SH | -6.2% | 同上 |
| 688279.SH | -5.5% | 同上 |

## 7. 运维说明

- **新增/调整规则**：改 `GateConfig` 阈值或扩展对应 `_check_*` 方法；每条触发的规则带层级标签写入 `RiskDecision.reasons`，可审计。
- **测试**：`tests/test_risk_gate.py`（17 项：L2 停机×4、L4 止损×4、L3 熔断×5、正常流×3、阈值对齐×1）。
- **人工复核**：盘前看 journal 第四节闸门预览；盘后看 PM"执行闸门"记录与成交对账。
- **紧急停机**：删除/清空 `live/risk_state.json` 不影响；如需长期停机，设 `no_buy_until` 为远期日期。
